# Enterprise-Invest — Database & Security Setup

Dokumentasi ini sengaja tidak menyimpan password, token, private key, atau credential yang dapat dipakai langsung.

## 1. Environment

Buat `.env` lokal/server dari secret manager atau `.env.example`. Jangan commit `.env`.

Wajib:

- DB_HOST
- DB_USER
- DB_PASSWORD
- DB_NAME
- DB_PORT
- JWT_ACCESS_SECRET (>= 32 karakter)
- JWT_REFRESH_SECRET (>= 32 karakter)
- JWT_ISSUER
- JWT_AUDIENCE

Opsional:

- JWT_ACCESS_EXPIRES_SECONDS=900
- JWT_REFRESH_EXPIRES_SECONDS=604800
- DB_SSL_FORCE=true
- DB_SSL_CA_PATH=/secure/path/ca.crt
- PORT=3000
- TRUST_PROXY=false
- JSON_BODY_LIMIT=100kb

Generate secret secara lokal dengan cryptographic random generator; jangan menggunakan password contoh dari dokumentasi.

## 2. Database migration

Setelah database PostgreSQL dibuat dan `.env` siap:

```bash
npm install
npm run db:migrate
```

Verifikasi:

```bash
npm run db:migrate:verify
```

Migration menyimpan status pada `schema_migrations` dan membuat `auth_sessions` untuk session/revocation/refresh-token rotation.

## 3. Authentication model

- Access token: JWT HS512, umur pendek.
- Refresh token: opaque random token, bukan JWT.
- Server hanya menyimpan SHA-256 refresh-token hash.
- Setiap refresh menghasilkan refresh token baru.
- Refresh token lama langsung dicabut dan ditautkan melalui `replaced_by`.
- Reuse token yang sudah dicabut menyebabkan sesi pengguna dicabut.
- Setiap access token membawa `sid` dan harus mempunyai session aktif di database.
- Role untuk API protected diambil ulang dari database sehingga perubahan role tidak menunggu JWT lama habis.

## 4. Dynamic CRUD

Dynamic CRUD bersifat deny-by-default.

Syarat:

1. Tabel harus terdaftar sebagai resource pada `app_menus`.
2. Role harus terdapat pada `roles_allowed`.
3. Tabel sistem (`login`, `auth_sessions`, `schema_migrations`) tidak boleh diakses melalui dynamic CRUD.
4. `activity_log` tidak dapat diubah/dihapus melalui dynamic CRUD.
5. Kolom credential/sensitive tidak dapat dibaca atau ditulis melalui dynamic CRUD.
6. DELETE hanya untuk `owner` dan `adminmaster`.
7. LIMIT default 100 dan maksimum 500.
8. Nama identifier divalidasi dan di-quote; nilai query selalu menggunakan parameter PostgreSQL.

Contoh request read:

```js
await window.DashboardSecurityContext.panggilMandorFrontend({
  aksi: 'ambil_data',
  target_tabel: 'nama_resource',
  kolom_diminta: ['kolom_A', 'kolom_B'],
  limit: 100,
  offset: 0
});
```

Contoh insert:

```js
await window.DashboardSecurityContext.panggilMandorFrontend({
  aksi: 'tambah_data',
  target_tabel: 'nama_resource',
  data_input: {
    nama_kolom_db1: 'Nilai Input 1'
  }
});
```

Contoh delete:

```js
await window.DashboardSecurityContext.panggilMandorFrontend({
  aksi: 'hapus_data',
  target_tabel: 'nama_resource',
  id_target: 5
});
```

## 5. Role menu

Format `roles_allowed` boleh berupa daftar role yang dipisahkan koma atau titik; backend melakukan normalisasi role.

```sql
INSERT INTO app_menus (menu_name, folder_name, roles_allowed, icon_visual, sort_order)
VALUES ('Nama Menu', 'nama-resource', 'owner,adminmaster', '📊', 1);
```

## 6. Sensitive operations

Endpoint berikut wajib menggunakan access token dan server-side authorization:

- `/api/owner/monitoring`
- `/api/settings/verify-device`
- `/api/owner/reset-hardware`
- `/api/owner/register-user`
- `/api/user/change-password`
- `/api/dynamic/crud`
- `/api/logout`

`/api/token/refresh` hanya menerima opaque refresh token yang tersimpan sebagai hash di database.

## 7. Security rules

Jangan pernah menyimpan berikut di repository:

- DB password
- JWT secret
- refresh token
- API key
- private key/certificate private key
- password admin
- password contoh yang menyerupai credential produksi

Gunakan environment variable/secret manager dan rotasi secret jika pernah terpapar.
